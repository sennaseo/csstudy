# 플레이 콘솔 "데이터 안전(Data safety)" 폼 답안지

csStudy · `io.github.sennaseo.csstudy` · 작성 기준일 2026-08-31

> 이 문서는 Play Console → 정책 → 앱 콘텐츠 → **데이터 안전** 폼을 채울 때 그대로 보고 입력하는 용도다.
> 모든 답은 실제 코드를 읽고 확인한 사실에 근거한다. 근거 파일을 각 항목에 적어뒀다.

## 결론부터 — 최종 신고 상태

**"이 앱은 필수 사용자 데이터 유형을 수집하거나 공유하지 않습니다"** 로 신고한다.

이유: 데이터 안전 폼에서 말하는 "수집(collection)"은 **개발자의 서버로 데이터가 전송되는 것**을 뜻한다.
csStudy는 (1) 기기 안에만 저장하고, (2) 동기화는 사용자 본인 소유 서버로만 가며, (3) 개발자가 운영하는 서버가 아예 존재하지 않는다.
구글 공식 기준상 **기기 내부에만 남는 데이터는 "수집"이 아니다.**

## 폼 진행 순서별 답안

### 0단계 — 데이터 수집 및 보안

| 콘솔 질문 | 답 | 이유 |
|---|---|---|
| 앱이 필수 사용자 데이터 유형을 수집하거나 공유하나요? | **아니요 (No)** | 개발자 서버가 존재하지 않는다. 학습 기록은 안드로이드 앱 내부 저장소(localStorage)에만 저장된다. 근거: `src/store/useStudyStore.ts` (키 `csStudy:v1`) |

> ⚠️ 여기서 **"아니요"** 를 고르면 아래 데이터 유형 체크리스트가 대부분 건너뛰어진다.
> 다만 콘솔이 보안 관련 질문은 계속 물어보므로 아래를 이어서 답한다.

### 보안 관행 (Security practices) — 위 답과 무관하게 물어봄

| 콘솔 질문 | 답 | 이유 |
|---|---|---|
| 데이터가 전송 중에 암호화되나요? | **해당 없음 / 예 (아래 설명 참고)** | 개발자에게 전송되는 데이터가 없어 원칙적으로 "해당 없음". 앱이 만드는 아웃바운드 요청은 **사용자 본인 서버로의 선택적 동기화 하나뿐이며**, **코드가 `https://` 로 시작하지 않는 주소를 아예 거부한다** (`getSyncConfig()` 가드). 즉 평문 전송 경로가 존재하지 않는다. 콘솔이 강제로 하나를 고르게 하면 **"예, 데이터가 전송 중에 암호화됩니다"**. 근거: `src/utils/sync.ts` (폰트는 앱에 내장돼 있어 네트워크 요청이 없다 — `src/index.css` 의 `@font-face` + `public/fonts/`) |
| 사용자가 데이터 삭제를 요청할 수 있나요? | **예 (Yes)** | 앱 삭제 또는 안드로이드 설정 → 앱 → csStudy → 저장공간 → 데이터 삭제로 전부 지워진다. 삭제 방법은 개인정보처리방침 9번에 명시했다. |
| 데이터 삭제 요청 URL | 별도 웹 URL 불필요 | 서버 보유 데이터가 없으므로 요청 창구가 필요 없다. 콘솔이 URL을 요구하면 개인정보처리방침 URL을 넣고, 방침 9번 "데이터 삭제 방법" 섹션이 답이다. |
| 앱이 Play Families 정책 대상(아동 타깃)인가요? | **아니요** | 개발자 학습용 앱이며 아동 대상이 아니다. 앱 콘텐츠 → 타겟 층 설정에서도 성인/13세+ 로 잡는다. |
| 독립적인 보안 검토를 받았나요? | **아니요** | 받지 않았다. 정직하게 아니요. (선택 항목이며 아니요라고 해서 불이익 없음) |

## 데이터 유형별 상세 — 왜 전부 "수집 안 함"인가

콘솔이 물어보는 유형을 하나씩 확인한 결과다. 심사에서 이의가 오면 이 표를 근거로 답변하면 된다.

| 데이터 유형 | 수집? | 근거 |
|---|---|---|
| 위치 (대략/정확) | ❌ 아니요 | `AndroidManifest.xml`에 위치 권한 선언 자체가 없다 |
| 개인 정보 (이름, 이메일, 주소, 전화번호, 인종, 정치성향 등) | ❌ 아니요 | 앱에 로그인/회원가입/입력 폼이 없다. 유일한 텍스트 입력은 동기화 설정의 서버 주소·토큰인데, 이건 기기 밖으로 나가지 않고 사용자 본인 서버 인증에만 쓰인다 |
| 금융 정보 | ❌ 아니요 | 앱 내 결제·구독이 없다. 결제 라이브러리 미포함 |
| 건강 및 피트니스 | ❌ 아니요 | 관련 코드 없음 |
| 메시지 (SMS, 이메일, 인앱 메시지) | ❌ 아니요 | 관련 권한·코드 없음 |
| 사진 및 동영상 | ❌ 아니요 | 카메라·저장소 권한 없음 |
| 오디오 (음성, 녹음) | ❌ 아니요 | 마이크 권한 없음. "말하기" 출제 유형은 화면에 표시만 하고 녹음하지 않는다 |
| 파일 및 문서 | ❌ 아니요 | 파일 접근 권한 없음 |
| 캘린더 | ❌ 아니요 | 권한 없음 |
| 연락처 | ❌ 아니요 | 권한 없음 |
| 앱 활동 (앱 상호작용, 인앱 검색, 설치된 앱 등) | ❌ 아니요 | 학습 진행도를 기록하긴 하지만 **기기 내부 저장이며 개발자에게 전송되지 않는다** → 구글 기준상 수집 아님. 근거: `src/store/useStudyStore.ts` `savePersisted()` |
| 웹 검색 기록 | ❌ 아니요 | 브라우징 기능 없음 |
| 앱 정보 및 실적 (크래시 로그, 진단, 성능) | ❌ 아니요 | 크래시 리포팅 SDK 미포함. `android/app/build.gradle`에 Crashlytics/Firebase 의존성 없음. `google-services.json` 파일 자체가 없어 Firebase 플러그인이 적용되지 않는다 |
| 기기 또는 기타 ID (광고 ID, 기기 ID) | ❌ 아니요 | 광고 SDK 없음. AAID 조회 코드 없음 |

## 🔴 판단이 필요한 지점 (senna가 결정해야 함)

### ✅ 판단 필요 1 (해결됨 2026-08-31) — 폰트 CDN 때문에 "기기 ID/IP"를 신고해야 하나?

**결론: 판단할 필요가 없어졌다. 폰트를 앱에 내장해서 CDN 요청 자체를 없앴다.**

**당시 상황**: 안드로이드 앱의 `index.html`(= `android/app/src/main/assets/public/index.html`)이 Google Fonts와 jsDelivr에서 폰트를 내려받았다. 요청이 나가면 IP 주소가 그쪽에 전달된다.

- 보수적인 해석: 제3자에게 IP가 간다 → "기기 또는 기타 ID"를 공유로 신고.
- 일반적 해석: 신고 불필요. 데이터 안전 폼은 "앱이 수집·전송하는 사용자 데이터"를 묻는 것이며, CDN에서 정적 자원을 내려받을 때 부수적으로 노출되는 IP는 구글이 말하는 수집 대상이 아니다.

두 번째 해석이 업계 표준이라고 봤지만 100% 확신은 아니었다. **그래서 해석에 기대는 대신 원인을 제거했다.**

**한 조치**: `index.html`의 CDN `<link>` 제거 → 폰트 woff2 5개를 `public/fonts/`에 넣고 `src/index.css`에 `@font-face`로 선언. Pretendard(2MB)는 실제로 메워주는 글자가 이모지뿐이라 제거하고 fallback을 `system-ui`로 끝냈다. 웹(GitHub Pages) 빌드도 동일하다.

**검증**: `android/app/src/main/assets/public/index.html`과 `dist/index.html`에 외부 URL **0개** (`grep -c 'https\?://'` → 0). CSS의 폰트 참조는 전부 `url(../fonts/*.woff2)` 상대 경로.

**결과**: 앱이 만드는 외부 요청은 **사용자 본인 서버로의 선택적 동기화 하나뿐**이다(기본 꺼짐). 따라서 기기 ID/IP 신고 논의는 종결. 개인정보처리방침 4번도 "외부 서비스로의 접속 (없음)"으로 갱신했다.

### 판단 필요 2 — 동기화 기능을 스토어 버전에서 유지할 것인가?

**사실**: 동기화는 사용자가 AWS를 직접 배포하고 URL+토큰을 손으로 입력해야만 동작한다(`src/store/useStudyStore.ts:859`의 `if (getSyncConfig())` 가드로 미설정 시 완전 no-op). 개발자 서버는 없다.

- **유지할 경우**: 지금 작성한 방침 그대로 쓰면 된다. 데이터 안전 답변은 "수집 안 함"이 유효하다 (사용자 본인 서버로의 전송은 개발자 수집이 아니다). 심사자가 물어보면 "사용자가 자신의 인프라를 직접 지정하는 BYOS(Bring Your Own Server) 방식"이라고 설명한다.
- **일반 사용자에겐 쓸모없는 기능**이므로 스토어 버전에서 숨기는 선택지도 있다. 그러면 방침 3번과 7번의 INTERNET 권한 설명이 단순해진다.

**나는 유지를 권한다.** 기능이 정직하게 문서화돼 있고 기본 꺼짐이라 심사 리스크가 낮다.

### 판단 필요 3 — 개인정보처리방침 URL을 어디에 둘 것인가

`store-assets/privacy-policy.html`을 GitHub Pages에 올려야 한다. 현재 저장소가 `sennaseo.github.io/csstudy/`로 배포되므로 다음 중 하나:
- `public/privacy-policy.html`로 복사 → 빌드 시 함께 배포 → `https://sennaseo.github.io/csstudy/privacy-policy.html`
- 별도 브랜치/저장소에 게시

**주의**: 이 URL은 앱이 스토어에 있는 동안 계속 살아 있어야 한다. 404가 되면 앱이 내려갈 수 있다.
